# SDSU Aztec Electric Racing (AER) - Formula SAE Driverless Vehicle ECU Firmware

This repository contains the bare-metal firmware for the vehicle's control ECU, built for San Diego State University (SDSU) Aztec Electric Racing (Project 44). It runs on an **STM32 NUCLEO-G474RE** board and handles the hard-real-time control loop (steering and braking actuation) — the companion to the [`aer_ws`](../aer_ws) ROS 2 workspace, which runs perception and planning on the NVIDIA Jetson Orin Nano Super.

This board deliberately does **not** run ROS 2 or micro-ROS. It stays plain C on top of the STM32 HAL so the control loop's timing stays fully deterministic, and talks to the Jetson over a custom protocol on a UART link, bridged into ROS 2 on the Jetson side by `aer_stm32_bridge`'s `uart_bridge_node`.

## Project Structure

* `AER-AUTON-Microcontroller-STM.ioc` — the CubeMX configuration file: pinout, clock tree, and peripheral setup. Open this in STM32CubeIDE to view/change pin assignments or clock settings (double-click it to open the Device Configuration Tool).
* `Core/Inc`, `Core/Src` — your application code. Hand-written logic belongs inside the `/* USER CODE BEGIN */` ... `/* USER CODE END */` blocks in `main.c` — anything outside those markers gets overwritten the next time code is regenerated from the `.ioc`.
* `Drivers/` — the STM32G4xx HAL and CMSIS libraries, generated by CubeMX. Not hand-edited.
* `Startup/` — the chip's startup assembly file.
* `STM32G474RETX_FLASH.ld` / `STM32G474RETX_RAM.ld` — linker scripts defining the chip's memory layout.

## Hardware

* **Board:** STM32 NUCLEO-64, MCU: STM32G474RE (Cortex-M4F, 170 MHz, 512 KB flash, 128 KB RAM)
* **Clock:** System clock run at the chip's max 170 MHz, driven from the internal HSI oscillator through the PLL
* **Transport to Jetson:** USART2 — during bring-up/bench testing this rides over the same USB cable used to flash the board (routed through the ST-Link's virtual COM port); on the vehicle it's wired directly to the Jetson's UART pins

## 🚀 Setup

### Prerequisites

1. **Install STM32CubeIDE** — the IDE used to write, build, flash, and debug this firmware. Download from [st.com/stm32cubeide](https://www.st.com/en/development-tools/stm32cubeide.html) (free, requires a (free) ST account).
2. **Install STM32CubeMX** — a separate tool from ST used for the pinout/clock/peripheral configuration (the `.ioc` file). Download from [st.com's "Get Software" page](https://www.st.com/en/development-tools/stm32cubemx.html) — pick the plain **STM32CubeMX** row (not STM32CubeMX2, which only covers the STM32C5/G5/H7P series), and make sure the OS dropdown matches your machine before downloading.

### Quick Start

1. Clone this repository:
   ```bash
   git clone https://github.com/Bazzarro/AER-AUTON-Microcontroller.git
   ```
2. Open **STM32CubeIDE**, then **File → Import... → General → Existing Projects into Workspace**, and select the cloned repo's root folder. CubeIDE will detect the project automatically — click **Finish**.
3. Once it's open in Project Explorer, build it once with **Project → Build Project** (or the hammer icon) to confirm everything compiles cleanly on your machine before changing anything.
4. To flash: connect the NUCLEO-G474RE over USB, then use the **Run** or **Debug** button in the toolbar — STM32CubeIDE talks to the board over the onboard ST-Link automatically, no extra drivers needed on most systems.

### Changing pin/clock configuration

Don't hand-edit `Drivers/` or the generated HAL init code directly. Instead, double-click the `.ioc` file to open the Device Configuration Tool, make your change there (Pinout & Configuration or Clock Configuration tabs), and click **Generate Code** — CubeIDE will regenerate the affected files while preserving anything inside your `USER CODE` blocks.
